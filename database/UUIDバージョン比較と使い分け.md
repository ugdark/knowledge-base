# UUIDバージョン比較と使い分け

## 概要

UUIDの主要バージョン（v1/v3/v4/v5/v6/v7/v8）の違いと使い分け。特に「ランダムなID」のv4、「時系列ソート可能」のv7、「同じ入力から同じIDを決定的に生成する」のv5の3つを軸に、DB主キー選定の観点も含めて整理する。

---

## 1. バージョン一覧

現行仕様は RFC 9562（2024年5月、旧 RFC 4122 を置き換え）。

| Ver | 生成方式 | 特徴 | 今使うか |
|---|---|---|---|
| v1 | タイムスタンプ + MACアドレス | 時刻情報を持つがビット配置がソートに向かない・MACアドレスが漏れる | 使わない（v7で置換） |
| v3 | 名前ベース（**MD5**） | v5と同じ発想のMD5版 | 使わない（v5で置換） |
| v4 | **全ランダム** | 最も普及。衝突確率は実用上無視できる | 順序不要なら可 |
| v5 | 名前ベース（**SHA-1**） | **同じ入力→必ず同じUUID**（決定的） | 固定化・冪等の用途で使う |
| v6 | v1の並び替え版 | v1互換が必要な移行用 | 新規では使わない |
| v7 | **Unixタイムスタンプ + ランダム** | **時系列ソート可能**。DB主キー向き | 新規の既定はこれ |
| v8 | 自由形式 | 実験・カスタム用の枠 | 特殊用途のみ |

## 2. 三大バージョンの違い

### v4: ランダム

- 122bitランダム。生成に入力も状態も不要
- 順序性ゼロ。「いつ作られたか」が漏れない（これが利点になる場面もある）

### v7: 時系列 + ランダム

- 先頭48bitがUnixミリ秒タイムスタンプ、残りがランダム
- **生成順≒辞書順**なのでB-treeインデックスと相性が良い
- 注意: IDから生成時刻が読める。外部公開IDにする場合は「作成日時を晒してよいか」を確認する

### v5: 名前ベース（決定的）

- **namespace（UUID）+ name（任意文字列）を SHA-1 でハッシュ**して生成
- 何度実行しても、誰が実行しても、**同じ入力なら同じUUID**になる
- ランダム性ゼロ。「生成」というより「導出」

```
uuid_v5(namespace, name) → 常に同じUUID

例（擬似コード）:
NS_TENANT = uuid_v5(NAMESPACE_DNS, "tenant.example.com")
id        = uuid_v5(NS_TENANT, "school:1234")  # 何度呼んでも同じ
```

- 標準namespaceとして DNS / URL / OID / X.500 が定義済み。独自namespaceは自分でUUIDを1つ決めて固定すればよい
- SHA-1は暗号用途としては非推奨だが、v5の目的は一意な導出であってセキュリティではないので実用上問題ない（気になるならv8でSHA-256実装も可）

## 3. v5の使いどころ（固定化）

「特定のものを固定化する」= 入力が同じなら常に同じIDになってほしい場面:

- **外部システムのキー→内部IDの安定変換**: 外部の `school_code` から内部UUIDを導出すれば、マッピングテーブルなしで再実行しても同じIDに着地する（ETL・データ連携の再取込で威力を発揮）
- **seedデータ・マスタデータのID固定**: 環境（dev/stage/prod）をまたいで同じマスタ行が同じIDになる。テストのフィクスチャも安定する
- **冪等キーの導出**: 「このリクエスト内容ならこのID」と決まるので、重複実行の検出に使える

逆に言うと、**入力を知っていれば誰でも同じIDを計算できる**から、推測されて困るIDには使わないこと。

## 4. DB主キーとしての選定

- **ランダムUUID（v4）を主キーにするとInnoDBで性能劣化する**。クラスタインデックスへの挿入位置がランダムになり、ページ分割が多発してページが不完全に埋まり、テーブルサイズが肥大する（下記参考リンクに計測あり）
- **v7（またはULID）なら挿入がほぼ末尾追記**になり、auto_incrementに近い挿入性能とキャッシュ効率を保てる
- MySQLに格納するなら `BINARY(16)` + `UUID_TO_BIN()`/`BIN_TO_UUID()`（8.0以降）。`CHAR(36)` は倍以上のサイズになる

## 5. 使い分け早見表

| 用途 | 推奨 |
|---|---|
| 新規テーブルの主キー | **v7**（時系列ソート・挿入性能） |
| 作成時刻を絶対に漏らしたくないID・トークン | v4 |
| 外部キーからの安定変換・seed固定・冪等キー | **v5**（決定的） |
| 旧v1システムとの互換 | v6 |
| 独自要件（別ハッシュ・独自レイアウト） | v8 |
