# Spec-Driven Development (SDD) ツール

## 概要

仕様駆動開発を支援するAI開発ツールの比較。OpenSpec、cc-sdd、GitHub Spec Kit、Kiroの4ツールを取り上げ、特徴・ワークフロー・評判を整理する。

---

## 1. OpenSpec (Fission-AI)

**リポジトリ**: https://github.com/Fission-AI/OpenSpec

### 概要
AI支援開発における人間とAIの期待値を実装前に揃えるための仕様駆動開発ツール

### 主な特徴
- APIキー不要
- 複数のAIコーディングツールに対応
- 2フォルダモデル（現在の仕様 + 変更提案）
- 仕様の反復的な改善が可能

### ワークフロー
1. 変更提案の下書き作成
2. 仕様のレビューと合意
3. 合意した仕様を参照してタスク実装
4. 変更をアーカイブして信頼できるドキュメントを更新

### 利点
- 機能間での差分を明示的かつ管理可能に保つ
- 新規・既存プロジェクト両方で機能
- 柔軟で標準化されたアプローチ

### アプローチ
実装前の仕様策定と合意形成を重視したプロセス/ワークフロー重視型

## 2. cc-sdd (gotalab)

**リポジトリ**: https://github.com/gotalab/cc-sdd

### 概要
AI駆動型の仕様生成により、ソフトウェア開発ワークフローを効率化するツール

### 主な特徴
- 構造化された要件・設計・タスクドキュメント生成
- 仕様ファーストの開発手法
- 依存関係追跡による並列タスク実行
- 7種類のAIコーディングエージェント統一ワークフロー
  - Claude, Copilot, Gemini など

### 技術スタック
- TypeScript 99.2%
- NPMパッケージ + CLI
- 13言語対応
- MITライセンス

### 価値提案
「会議、ドキュメント作成、コンテキストの分散により失われる開発時間の70%を削減」

AI駆動開発ライフサイクル (AI-DLC) による構造化アプローチを提供

### 効果
開発時間を数週間から数時間に短縮

### アプローチ
具体的なツール実装（TypeScript CLI）を提供

## 3. GitHub Spec Kit (GitHub)

**公式サイト**: https://github.blog/ai-and-ml/generative-ai/spec-driven-development-with-ai-get-started-with-a-new-open-source-toolkit/

### 概要
GitHubが2025年9月にリリースしたオープンソースのSDD用CLIツール

### 主な特徴
- GitHub Copilot、Claude Code、Gemini CLIなどと連携
- 4フェーズの構造化ワークフロー
- 仕様を中心としたエンジニアリングプロセス
- オープンソース（無料）

### ワークフロー（4フェーズ）
1. **Specify**: 仕様の作成
2. **Plan**: 計画の策定
3. **Tasks**: タスク分解とチェックリスト作成
4. **Implement**: 実装

各フェーズには明確なチェックポイントがあり、検証が完了するまで次のフェーズに進まない

### 利点
- 標準化されたプロセス
- 主要なAIコーディングツールとの統合
- 推測を減らし、高品質なコードを生成

### アプローチ
業界標準を目指したオープンソースツールキット

## 4. Kiro

**公式サイト**: https://kiro.dev/

### 概要
"vibe coding"（曖昧な指示によるコード生成）から脱却し、プログラマーとAIエージェント間の持続可能なコラボレーションを実現

### 主な特徴
- バージョン管理されたアーティファクト
- AIエージェントのガイド/バリデーション機能
- 大規模コードベースでの混乱を防ぐ
- AIエージェントの「北極星」として機能

### 哲学
仕様がAIエージェントの作業の指針となり、参照先となり、検証基準となる。これによりエージェントは迷うことなく大きなタスクを処理できる

### 利点
- 大規模プロジェクトでの制御性向上
- AIエージェントとの永続的なコラボレーション
- プロンプト駆動の混乱を抑制

### アプローチ
バージョン管理とアーティファクトベースの構造化開発

## 比較まとめ

| 項目 | OpenSpec | cc-sdd | GitHub Spec Kit | Kiro |
|------|----------|--------|-----------------|------|
| **タイプ** | ワークフロー/プロセス | 具体的ツール（CLI） | オープンソースCLI | IDE/プラットフォーム |
| **実装** | ツール非依存 | TypeScript NPMパッケージ | GitHub製CLIツール | バージョン管理アーティファクト |
| **焦点** | 仕様の合意形成 | 仕様生成の自動化 | 4フェーズワークフロー | AIとの持続的コラボ |
| **依存性** | APIキー不要 | AIエージェント連携 | GitHub/Copilot/Claude等 | バージョン管理システム |
| **対応範囲** | 複数AIツール対応 | 7種類のAIエージェント | Copilot/Claude/Gemini | 大規模コードベース |
| **リリース** | - | - | 2025年9月 | - |

### 共通点
- 仕様駆動開発 (Spec-Driven Development) の手法
- AI支援開発の効率化とコンテキスト管理
- 実装前の仕様策定を重視

### 選択ガイド
- **OpenSpec**: プロセス改善、柔軟性重視、既存ツールとの統合
- **cc-sdd**: 即座に使えるツール、TypeScript開発、複数AIエージェント統一管理
- **GitHub Spec Kit**: GitHub/Copilot利用者、標準化されたワークフロー、オープンソース
- **Kiro**: 大規模プロジェクト、バージョン管理重視、AIとの長期コラボ

## Spec-Driven Development (SDD) とは

仕様を先に定義し、その仕様に基づいて開発を進める手法。AI開発においては特に重要で、以下の利点がある:

1. **コンテキストの明確化**: AIと人間の認識のズレを防ぐ
2. **効率化**: 手戻りの削減
3. **ドキュメント化**: 自動的に仕様書が残る
4. **並列作業**: 明確な仕様により複数タスクを並行実行可能

## 評判・実績比較（2025年最新）

### GitHub Spec Kit

**人気度**:
- 40,623 stars (GitHub)
- 最初の1週間で16,000 stars獲得
- 50カ国以上から開発者が参加

**評判**:
- 「2026年最もクリーンなspec-first実装方法の1つ」
- クリーンで信頼性の高いコード生成を促進
- 日本でもcocone engineeringが試験導入
- **実験的ツール**とGitHub自身が明言（「本番環境ではない」）
- 「Markdownの海」「長いエージェント実行時間」との批判
- 「AIがspec以上のことをしない」（常識的判断もしない）
- 「Waterfallの再来では？」という懸念の声

**ドキュメント**:
- 英語中心
- 日本語の公式ドキュメントなし
- 日本語レビュー記事は散見される

**現状**:
- version 0.0.30+ (急速に開発中)
- コミュニティからのフィードバックを積極収集中

---

### cc-sdd

**人気度**:
- 1,900+ stars (GitHub)
- 日本人開発者（Gota氏 @gota_bara）が作成

**評判**:
- **実務での成功事例が豊富**（Zenn記事多数）
  - 「実務で使い倒したので丁寧に解説」
  - 「国産の仕様駆動開発ツール cc-sdd を推していきたい」
- GIGAZINEで紹介（日本語対応を高く評価）
- **次に実行するコマンドを提示**してくれるため迷わない
- 手戻り防止に効果的（実務ユーザーの証言）
- AIとの認識齟齬による手戻りを大幅削減

**ドキュメント**:
- **公式日本語ドキュメント完備**
  - `README_ja.md`
  - `docs/guides/ja/spec-driven.md`
- 日本語での使用: `npx cc-sdd@latest --lang ja`
- Claude Code専用オプション: `npx cc-sdd@latest --claude --lang ja`

**ワークフロー**:
```
steering → spec-init → spec-design → spec-tasks → spec-impl
```

**技術的特徴**:
- Amazon Kiroのspecモードを参考に開発
- 国産ツールのため質問・issueも日本語でOK

### 業界全体のSDD評価（2025年）

**賛成派の意見**:
- AI開発における「認識のズレ」を効果的に防止
- 手戻り削減、ドキュメント自動化
- 大規模プロジェクトでの制御性向上
- テスト駆動開発との親和性

**批判派の意見**:
- 「Markdownが多すぎて読むのが大変」
- 「AIが仕様以外の常識的判断をしなくなる」（マイクロマネジメント化）
- 「ウォーターフォール開発の復活では？」
- 「vibe coding（自然言語で気軽に開発）の方が速い場合もある」
- 「AIが最終的に全ての指示に従わないことがある」

**業界の位置づけ**:
- ThoughtWorksのTechnology Radarで「Assess（評価段階）」
- 2025年時点で20以上のプラットフォームが乱立
- ベストプラクティスについて明確なコンセンサスはまだない

### 推奨事項（日本語環境での開発）

**cc-sddを推奨する理由**:
1. **日本語ドキュメント・サポート完備**
2. **Claude Code専用オプション** (`--claude --lang ja`)
3. **実務での成功事例が豊富**（Zenn記事多数）
4. **国産なので質問・issueも日本語でOK**
5. **次のステップを提示してくれる**優れたUX
6. **手戻り防止の実証済み効果**

**GitHub Spec Kitを検討すべきケース**:
- グローバルチームでの開発
- 英語ドキュメントに抵抗がない
- GitHub製ツールへの信頼性を重視
- 最新の実験的機能を試したい
