# モダン認証のベストプラクティス (2025年版)

## 概要

Cookie、JWT、セッション認証の使い分けと実装指針をまとめる。Session Cookie（Stateful）とJWT（Stateless）の比較、Cookie セキュリティ属性、Access Token + Refresh Tokenパターン、各言語での実装例（Node.js、Spring Boot、Scala）を含む。

---

## 1. 認証方式の比較

### 1.1 Session Cookie (Stateful)

**概要**:
- サーバー側でセッション状態を管理（DB/Redis）
- CookieにはランダムなセッションIDのみ格納
- 各リクエストでセッションIDを検証

**実装例**:
```http
Set-Cookie: sessionId=random_unique_value;
  HttpOnly;
  Secure;
  SameSite=Strict;
  Max-Age=3600;
```

**メリット**:
- 即座にセッション無効化可能（ログアウト、アカウント停止）
- シンプルで実績がある
- セキュリティ制御が強力（"全デバイスでログアウト"など）
- 実装が容易

**デメリット**:
- 各リクエストでDB/Redisアクセスが必要（レイテンシ）
- サーバー間でセッション共有が必要（スケーリング時）
- 分散システムには不向き

---

### 1.2 JWT (Stateless)

**概要**:
- トークン自体に認証情報を含む（自己完結型）
- サーバー側でセッション管理不要
- 署名検証のみで認証可能

**実装例**:
```http
Set-Cookie: accessToken=eyJhbGc...;
  HttpOnly;
  Secure;
  SameSite=Strict;
  Max-Age=900;  // 15分
```

**メリット**:
- Stateless（サーバー側でセッション保存不要）
- スケーリングが容易（各サーバーが独立して検証可能）
- マイクロサービスに適している
- クロスドメイン認証が可能

**デメリット**:
- 即座に無効化できない（有効期限まで有効）
- 無効化にはブロックリスト管理が必要（→Statefulになる）
- トークンサイズが大きい
- 実装が複雑

## 2. 使い分け指針

### 2.1 Session Cookieを使うべき場合

**適用ケース**:
- 単一のWebアプリケーション（モノリシック）
- 伝統的なSSR（Server-Side Rendering）
- SPAで同一ドメインからのアクセス
- eコマースサイト
- 管理画面・社内ツール
- B2Bアプリケーション

**理由**:
- シンプルで十分
- セキュリティ要件（即座ログアウト）を満たしやすい
- 実装コストが低い

---

### 2.2 JWTを使うべき場合

**適用ケース**:
- マイクロサービスアーキテクチャ
- 複数サービス間での認証情報共有
- 外部APIとの連携
- モバイルアプリ + APIバックエンド
- IoTデバイス
- SSO（シングルサインオン）

**理由**:
- サービス間でセッション共有が不要
- 各サービスが独立してトークン検証可能
- 分散システムに適している

---

### 2.3 ハイブリッドアプローチ

**概要**:
メイン認証にSession Cookie、特定用途にJWTを併用

**実装例**:
```
- ユーザーログイン認証 → Session Cookie
- 外部API連携用トークン → JWT（短命）
- サービス間通信 → JWT
```

**メリット**:
- 両方の利点を活用
- セキュリティと柔軟性のバランス

## 3. Cookie セキュリティ属性（必須設定）

### 3.1 必須属性

| 属性 | 値 | 目的 |
|------|-----|------|
| `HttpOnly` | `true` | XSS攻撃防止（JavaScriptからアクセス不可） |
| `Secure` | `true` | HTTPS通信のみ（盗聴防止） |
| `SameSite` | `Strict` または `Lax` | CSRF攻撃防止 |

### 3.2 SameSite属性の選択

**Strict**:
- 最も厳格
- 他サイトからのリクエストに一切Cookieを含めない
- 認証Cookieに推奨

**Lax**:
- トップレベルナビゲーション（aタグクリックなど）では送信
- POSTリクエストでは送信しない
- ユーザビリティとセキュリティのバランス

**None**:
- クロスサイトリクエストでも送信
- `Secure`属性必須
- 特別な理由がない限り非推奨

### 3.3 実装例

```javascript
// 認証用Cookie（推奨設定）
res.cookie('sessionId', value, {
  httpOnly: true,
  secure: true,
  sameSite: 'strict',
  maxAge: 3600000  // 1時間
});
```

## 4. JWT使用時のベストプラクティス

### 4.1 Access Token + Refresh Token パターン

**推奨構成**:
```
Access Token:
  - 有効期限: 5-15分（短命）
  - 用途: API リクエスト認証
  - 格納: HttpOnly Cookie

Refresh Token:
  - 有効期限: 7-30日（長命）
  - 用途: Access Token再発行
  - 格納: HttpOnly Cookie
  - DB管理: 無効化可能にする
```

**フロー**:
1. ログイン成功 → Access Token + Refresh Token発行
2. APIリクエスト → Access Token検証
3. Access Token期限切れ → Refresh Tokenで再発行
4. Refresh Token期限切れ → 再ログイン

**メリット**:
- Access Tokenが短命なので漏洩リスク低減
- Refresh TokenはDB管理で無効化可能

### 4.2 JWT格納場所

| 格納場所 | 評価 | 理由 |
|---------|------|------|
| `localStorage` | 絶対ダメ | XSS攻撃で簡単に盗まれる |
| `sessionStorage` | ダメ | XSS攻撃で盗まれる |
| `HttpOnly Cookie` | 推奨 | JavaScriptからアクセス不可 |

### 4.3 JWTペイロード設計

**含めるべき情報**:
- `sub`: ユーザーID
- `iat`: 発行時刻
- `exp`: 有効期限
- `jti`: トークンID（オプション、無効化管理用）

**含めてはいけない情報**:
- パスワード
- 機密性の高い個人情報
- 大量のデータ（トークンサイズ増大）

**理由**: JWTはBase64エンコードされているだけで暗号化されていない

### 4.4 無効化戦略

JWTは本質的に無効化できないため、以下の戦略が必要：

**1. ブロックリスト方式**:
```
Redis/DBに無効化されたJWTのjtiを保存
各リクエストでチェック

デメリット: Statefulになる（JWTの利点が減る）
```

**2. 短命トークン + Refresh Token**:
```
Access Tokenを短命に
Refresh TokenはDBで管理（無効化可能）

メリット: 無効化の遅延が最小（最大15分など）
```

**3. バージョニング**:
```
ユーザーごとにtokenVersionをDB管理
JWTにversionを含める
ログアウト時にversionを更新

メリット: 全トークンを一括無効化可能
```

## 5. 実装チェックリスト

### 5.1 Session Cookie実装時

- [ ] HttpOnly, Secure, SameSite属性を設定
- [ ] セッションタイムアウトを適切に設定
- [ ] ログアウト時にセッションを確実に削除
- [ ] CSRF対策を実装（トークンまたはSameSite）
- [ ] セッション固定攻撃対策（ログイン時にセッションID再生成）

### 5.2 JWT実装時

- [ ] HttpOnly Cookieに格納（localStorageは使わない）
- [ ] Access Tokenを短命に（5-15分）
- [ ] Refresh Tokenパターンを実装
- [ ] Refresh TokenをDB管理（無効化可能に）
- [ ] 強力な署名アルゴリズム使用（HS256以上、推奨RS256）
- [ ] JWTに機密情報を含めない
- [ ] 署名検証を確実に実施
- [ ] HTTPS必須（本番環境）

## 6. よくある間違い

### 6.1 localStorageにJWT保存

**絶対ダメ**:
```javascript
// XSS攻撃で簡単に盗まれる
localStorage.setItem('token', jwt);
```

**正しい**:
```javascript
// HttpOnly Cookieで保存（サーバー側で設定）
res.cookie('token', jwt, {
  httpOnly: true,
  secure: true,
  sameSite: 'strict'
});
```

### 6.2 JWTを無効化なしで長期使用

**危険**:
```
有効期限: 30日のAccess Token
→ 漏洩したら30日間悪用される
```

**安全**:
```
Access Token: 15分
Refresh Token: 7日（DB管理で無効化可能）
```

### 6.3 CSRF対策なしでCookie使用

**脆弱**:
```
SameSite属性なし
CSRFトークンなし
→ CSRF攻撃可能
```

**安全**:
```
SameSite=Strict または Lax
または
CSRFトークン実装
```

## 7. 実装例（コード付き）

### 7.1 推奨される有効期限設定

| トークン種別 | 用途 | 推奨有効期限 | 理由 |
|------------|------|------------|------|
| **Access Token** | API認証 | **5-15分** | 漏洩時の影響を最小化 |
| **Refresh Token** | トークン再発行 | **7-14日** | UX（再ログイン頻度）とセキュリティのバランス |
| **Session Cookie** | セッション管理 | **1-24時間** | アプリケーション特性に応じて |

**セキュリティレベル別の推奨値**:
```
高セキュリティ（銀行など）:
  Access Token: 5分
  Refresh Token: 7日

一般Webアプリ:
  Access Token: 15分
  Refresh Token: 14日

低頻度アクセスアプリ:
  Access Token: 1時間
  Refresh Token: 30日
```

### 7.2 Node.js (Express) 実装例

#### 7.2.1 JWT生成とCookie設定

```javascript
const jwt = require('jsonwebtoken');

// ログイン成功時
app.post('/api/login', async (req, res) => {
  const { username, password } = req.body;

  // ユーザー認証（省略）
  const user = await authenticateUser(username, password);

  // Access Token生成（15分有効）
  const accessToken = jwt.sign(
    {
      userId: user.id,
      username: user.username,
      type: 'access'
    },
    process.env.ACCESS_TOKEN_SECRET,
    { expiresIn: '15m' }  // 15分
  );

  // Refresh Token生成（7日有効）
  const refreshToken = jwt.sign(
    {
      userId: user.id,
      type: 'refresh',
      jti: crypto.randomUUID()  // 無効化管理用ID
    },
    process.env.REFRESH_TOKEN_SECRET,
    { expiresIn: '7d' }  // 7日
  );

  // Refresh TokenをDBに保存（無効化可能にする）
  await saveRefreshToken(user.id, refreshToken);

  // Access Token を HttpOnly Cookie にセット
  res.cookie('accessToken', accessToken, {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',  // 本番環境ではHTTPS必須
    sameSite: 'strict',
    maxAge: 15 * 60 * 1000  // 15分（ミリ秒）
  });

  // Refresh Token を HttpOnly Cookie にセット
  res.cookie('refreshToken', refreshToken, {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'strict',
    maxAge: 7 * 24 * 60 * 60 * 1000  // 7日（ミリ秒）
  });

  res.json({ message: 'Login successful' });
});
```

#### 7.2.2 トークンリフレッシュ（Refresh Token Rotation）

```javascript
// Refresh Token でAccess Token再発行
app.post('/api/refresh', async (req, res) => {
  const { refreshToken } = req.cookies;

  if (!refreshToken) {
    return res.status(401).json({ error: 'No refresh token' });
  }

  try {
    // Refresh Token検証
    const decoded = jwt.verify(refreshToken, process.env.REFRESH_TOKEN_SECRET);

    // DBで有効性確認（ログアウト済みでないか）
    const isValid = await verifyRefreshToken(decoded.userId, decoded.jti);
    if (!isValid) {
      return res.status(401).json({ error: 'Invalid refresh token' });
    }

    // 新しいAccess Token生成
    const newAccessToken = jwt.sign(
      {
        userId: decoded.userId,
        type: 'access'
      },
      process.env.ACCESS_TOKEN_SECRET,
      { expiresIn: '15m' }
    );

    // 【重要】新しいRefresh Tokenも生成（Rotation）
    const newRefreshToken = jwt.sign(
      {
        userId: decoded.userId,
        type: 'refresh',
        jti: crypto.randomUUID(),
        previousJti: decoded.jti  // 前のトークンIDを記録
      },
      process.env.REFRESH_TOKEN_SECRET,
      { expiresIn: '7d' }
    );

    // 古いRefresh Tokenを無効化
    await invalidateRefreshToken(decoded.jti);

    // 新しいRefresh TokenをDBに保存
    await saveRefreshToken(decoded.userId, newRefreshToken);

    // 新しいトークンをCookieにセット
    res.cookie('accessToken', newAccessToken, {
      httpOnly: true,
      secure: process.env.NODE_ENV === 'production',
      sameSite: 'strict',
      maxAge: 15 * 60 * 1000
    });

    res.cookie('refreshToken', newRefreshToken, {
      httpOnly: true,
      secure: process.env.NODE_ENV === 'production',
      sameSite: 'strict',
      maxAge: 7 * 24 * 60 * 60 * 1000
    });

    res.json({ message: 'Tokens refreshed' });

  } catch (error) {
    return res.status(401).json({ error: 'Invalid token' });
  }
});
```

#### 7.2.3 ログアウト実装

```javascript
// ログアウト
app.post('/api/logout', async (req, res) => {
  const { refreshToken } = req.cookies;

  if (refreshToken) {
    try {
      const decoded = jwt.verify(refreshToken, process.env.REFRESH_TOKEN_SECRET);
      // Refresh Tokenを無効化
      await invalidateRefreshToken(decoded.jti);
    } catch (error) {
      // トークンが無効でもログアウトは続行
    }
  }

  // Cookieをクリア
  res.clearCookie('accessToken');
  res.clearCookie('refreshToken');

  res.json({ message: 'Logged out' });
});
```

#### 7.2.4 認証ミドルウェア

```javascript
// Access Token検証ミドルウェア
const authenticateToken = (req, res, next) => {
  const token = req.cookies.accessToken;

  if (!token) {
    return res.status(401).json({ error: 'Authentication required' });
  }

  try {
    const decoded = jwt.verify(token, process.env.ACCESS_TOKEN_SECRET);
    req.user = decoded;
    next();
  } catch (error) {
    if (error.name === 'TokenExpiredError') {
      return res.status(401).json({
        error: 'Token expired',
        code: 'TOKEN_EXPIRED'  // クライアント側でRefresh実行
      });
    }
    return res.status(403).json({ error: 'Invalid token' });
  }
};

// 使用例
app.get('/api/protected', authenticateToken, (req, res) => {
  res.json({
    message: 'Protected data',
    user: req.user
  });
});
```

### 7.3 Session Cookie実装例（Express Session）

```javascript
const session = require('express-session');
const RedisStore = require('connect-redis').default;
const { createClient } = require('redis');

// Redisクライアント作成
const redisClient = createClient({
  host: 'localhost',
  port: 6379
});
redisClient.connect();

// Session設定
app.use(session({
  store: new RedisStore({ client: redisClient }),
  secret: process.env.SESSION_SECRET,
  name: 'sessionId',  // Cookie名
  resave: false,
  saveUninitialized: false,
  cookie: {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'strict',
    maxAge: 1000 * 60 * 60 * 24  // 24時間（ミリ秒）
  }
}));

// ログイン
app.post('/api/login', async (req, res) => {
  const { username, password } = req.body;
  const user = await authenticateUser(username, password);

  if (user) {
    // セッションにユーザー情報を保存
    req.session.userId = user.id;
    req.session.username = user.username;

    res.json({ message: 'Login successful' });
  } else {
    res.status(401).json({ error: 'Invalid credentials' });
  }
});

// ログアウト
app.post('/api/logout', (req, res) => {
  req.session.destroy((err) => {
    if (err) {
      return res.status(500).json({ error: 'Logout failed' });
    }
    res.clearCookie('sessionId');
    res.json({ message: 'Logged out' });
  });
});

// 認証チェックミドルウェア
const requireAuth = (req, res, next) => {
  if (!req.session.userId) {
    return res.status(401).json({ error: 'Authentication required' });
  }
  next();
};

// 保護されたルート
app.get('/api/profile', requireAuth, (req, res) => {
  res.json({
    userId: req.session.userId,
    username: req.session.username
  });
});
```

### 7.4 Java (Spring Boot) 実装例

#### 7.4.1 JWT生成

```java
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.SignatureAlgorithm;
import io.jsonwebtoken.security.Keys;
import java.security.Key;
import java.util.Date;

@Service
public class JwtService {

    private final Key accessTokenSecret = Keys.secretKeyFor(SignatureAlgorithm.HS256);
    private final Key refreshTokenSecret = Keys.secretKeyFor(SignatureAlgorithm.HS256);

    // Access Token有効期限: 15分
    private static final long ACCESS_TOKEN_VALIDITY = 15 * 60 * 1000;

    // Refresh Token有効期限: 7日
    private static final long REFRESH_TOKEN_VALIDITY = 7 * 24 * 60 * 60 * 1000;

    public String generateAccessToken(Long userId, String username) {
        return Jwts.builder()
            .setSubject(userId.toString())
            .claim("username", username)
            .claim("type", "access")
            .setIssuedAt(new Date())
            .setExpiration(new Date(System.currentTimeMillis() + ACCESS_TOKEN_VALIDITY))
            .signWith(accessTokenSecret)
            .compact();
    }

    public String generateRefreshToken(Long userId) {
        return Jwts.builder()
            .setSubject(userId.toString())
            .claim("type", "refresh")
            .claim("jti", UUID.randomUUID().toString())
            .setIssuedAt(new Date())
            .setExpiration(new Date(System.currentTimeMillis() + REFRESH_TOKEN_VALIDITY))
            .signWith(refreshTokenSecret)
            .compact();
    }
}
```

```java
    }
}
```

### 7.5 Scala実装例（参考）

```scala
import pdi.jwt.{Jwt, JwtAlgorithm, JwtClaim}
import java.time.Instant
import scala.concurrent.duration._

object JwtService {

  private val accessTokenSecret = sys.env.getOrElse("ACCESS_TOKEN_SECRET", "secret")
  private val refreshTokenSecret = sys.env.getOrElse("REFRESH_TOKEN_SECRET", "secret")

  // Access Token: 15分
  private val accessTokenExpiry = 15.minutes

  // Refresh Token: 7日
  private val refreshTokenExpiry = 7.days

  def generateAccessToken(userId: Long, username: String): String = {
    val now = Instant.now()
    val claim = JwtClaim(
      content = s"""{"userId":$userId,"username":"$username","type":"access"}""",
      issuedAt = Some(now.getEpochSecond),
      expiration = Some(now.plusSeconds(accessTokenExpiry.toSeconds).getEpochSecond)
    )
    Jwt.encode(claim, accessTokenSecret, JwtAlgorithm.HS256)
  }

  def generateRefreshToken(userId: Long): String = {
    val now = Instant.now()
    val jti = java.util.UUID.randomUUID().toString
    val claim = JwtClaim(
      content = s"""{"userId":$userId,"type":"refresh","jti":"$jti"}""",
      issuedAt = Some(now.getEpochSecond),
      expiration = Some(now.plusSeconds(refreshTokenExpiry.toSeconds).getEpochSecond)
    )
    Jwt.encode(claim, refreshTokenSecret, JwtAlgorithm.HS256)
  }

  def verifyAccessToken(token: String): Option[JwtClaim] = {
    Jwt.decode(token, accessTokenSecret, Seq(JwtAlgorithm.HS256)).toOption
  }
}
```

```scala
        maxAge = Some(7 * 24 * 60 * 60),  // 7日（秒）
        path = Some("/"),
        sameSite = Some(SameSite.Strict)
      )

      setCookie(accessCookie, refreshCookie) {
        complete("Login successful")
      }
    }
  }
}
```

### 7.6 Cookie有効期限の指定方法まとめ

| 言語/FW | パラメータ名 | 単位 | 例（15分） |
|---------|------------|------|-----------|
| **Express (Node.js)** | `maxAge` | ミリ秒 | `maxAge: 15 * 60 * 1000` |
| **Spring Boot** | `maxAge` | 秒 | `maxAge(15 * 60)` |
| **Pekko HTTP (Scala)** | `maxAge` | 秒（Option） | `maxAge = Some(15 * 60)` |
| **標準HTTP Header** | `Max-Age` | 秒 | `Max-Age=900` |

**重要な注意点**:
- `maxAge` vs `expires`: 両方設定した場合は**後に定義した方**が優先される
- `maxAge`: 現在時刻からの相対時間（推奨）
- `expires`: 絶対日時（タイムゾーンに注意）

### 7.7 Refresh Token Rotationの重要性

**なぜRotationが必要か**:
```
Refresh Tokenが盗まれた場合:
  Rotationなし → 有効期限まで使い放題（最大7-30日）
  Rotationあり → 正規ユーザーが次回使用時に検知可能
```

**検知の仕組み**:
1. 攻撃者がRefresh Tokenを盗んで使用 → 新しいRefresh Token発行、古いToken無効化
2. 正規ユーザーが古いTokenで再アクセス → エラー検知
3. システムが異常を検知 → 全トークン無効化、再ログイン要求

**実装例（7.2.2参照）**:
- Refresh Token使用時に必ず新しいTokenを発行
- 古いTokenを即座に無効化
- `previousJti`で履歴を追跡

## 9. まとめ

### 選択フローチャート

```
[認証方式を選ぶ]
    |
    ├─ 単一Webアプリ？
    |    └─ YES → Session Cookie
    |
    ├─ マイクロサービス/API中心？
    |    └─ YES → JWT (Access + Refresh Token)
    |
    └─ 両方必要？
         └─ YES → ハイブリッド
```

### 鉄則

1. **HTTPSは必須**（本番環境）
2. **HttpOnly, Secure, SameSite属性は必須**
3. **localStorageにトークン保存は絶対ダメ**
4. **JWTは短命に（5-15分）**
5. **即座ログアウトが必要ならSession Cookie**
6. **分散システムならJWT**
7. **迷ったらSession Cookieから始める**（シンプル・安全）
