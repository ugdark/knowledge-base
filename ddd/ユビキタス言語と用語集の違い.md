# ユビキタス言語と用語集の違い

## 概要

「ユビキタス言語って用語集のことでしょ？」に対する答え。**違う**。用語集は「単語帳」、ユビキタス言語は「実際に全員がその言葉で暮らすこと」。この違いをできるだけ平易にまとめる。

---

## 一言でいうと

- **用語集**: 言葉の意味を書いて置いておく**ドキュメント**。作って終わりでも成立する
- **ユビキタス言語**: 会話・チケット・設計書・**コード**の全部で、全員が同じ言葉を実際に**使い続ける活動**。ドキュメントはその副産物

英単語帳を持っていることと、英語で生活することの違い、と言えば分かるでしょ。単語帳（用語集）を持っていても、しゃべらなければ（ユビキタス言語でなければ）英語は身につかない。

## 何が起きるかで比べる

シナリオ: 営業は「お客様」、POは「会員」、エンジニアはコードで `user`、DBでは `customer` と呼んでいる。

### 用語集だけがある場合

```
用語集.xlsx
  お客様 = 会員 = user = customer （全部同じ意味です）
```

- 「同じ意味です」と**翻訳表**を作って解決した気になる
- MTGのたびに頭の中で翻訳が走る。翻訳ミスがバグになる
- 用語集は更新されなくなり、半年後には誰も見ない

### ユビキタス言語がある場合

```
決定: この文脈では「会員（member）」と呼ぶ。他の呼び方は使わない。
```

- 会話も「会員」、チケットも「会員」、コードも `Member`、DBも `members`
- **翻訳が消える**。営業の発言がそのままクラス名になる
- 「会員」の意味が変わったら、会話もコードも一緒に変える（生きた言語として育てる）

## 比較表

| | 用語集 | ユビキタス言語 |
|---|---|---|
| 正体 | ドキュメント（単語帳） | チームの習慣・規律 |
| ゴール | 意味を調べられること | **翻訳をなくすこと** |
| 別名の扱い | 「AはBとも呼ぶ」と併記しがち | **1つに決めて他を捨てる** |
| コードとの関係 | 無関係でも成立する | **コードに必ず反映される**（クラス名・API・テーブル名） |
| 誰が作る | 誰か1人が書ける | エンジニア外も含めた全員の合意が必要 |
| 更新 | 忘れられがち | 会話で毎日使うので、ズレたらすぐ気づく |
| 適用範囲 | 会社全体で1冊になりがち | **境界づけられたコンテキストごと**に別の言語でよい |

## よくある勘違い

### 「用語集を作ったのでユビキタス言語はあります」

無い。用語集に「トップページ＝作品一覧ページ」と書いてあっても、会話で「トップページ」と言い続けているなら、それはただの単語帳。**実際に使う言葉を1つに変えたとき**に初めてユビキタス言語になる。

### 「全社で統一しないといけない」

しなくていい。DDDでは境界づけられたコンテキスト（Bounded Context）ごとに言語が違っていい。販売の文脈の「商品」と、在庫の文脈の「商品」は別物でOK。**1つの文脈の中でだけ、絶対にブレさせない**のがルール。

### 「エンジニアが決めればいい」

ダメ。ドメインの言葉はドメインに詳しい人（PO・営業・CS）が持っている。エンジニアだけで決めると、実装都合の名前（`data`、`info`、`manager`）が混ざって言語が腐る。

## じゃあ用語集は無駄なのか

無駄じゃない。**ユビキタス言語の「記録先」として**用語集は有効。順序が大事:

1. 全員で言葉を1つに決める（←ここがユビキタス言語）
2. 決めた結果を用語集に記録する（←これは副産物）

逆（用語集を書いてから浸透させよう）は大抵失敗する。言葉は使わないと定着しないから。
