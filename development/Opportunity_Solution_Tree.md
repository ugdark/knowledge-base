# Opportunity Solution Tree（OST）

## 概要

Teresa Torres が著書『Continuous Discovery Habits』で提唱した、望む成果（outcome）に至る道筋を木で描くプロダクトディスカバリーの手法。顧客のニーズ（opportunity）を先に整理し、解決策（solution）と検証（assumption test）を枝として繋ぐ。

---

## 1. 位置づけ

- Torres は OST を「望む成果に至るために取りうる道筋を視覚的に表すシンプルな方法」と説明している。
- 目的は、プロダクトトリオ（PM・デザイナー・エンジニア）が最善の道筋を描き、継続的ディスカバリーの中でチームの認識を揃えること。
- 「Continuous Discovery」は、プロダクトを作るチームが最低でも毎週顧客と接点を持つことを指す。OST はその習慣を支える道具。
- 名前の整理: Discovery は習慣・活動の名前、OST はそれを可視化する道具の名前。

## 2. 木の構造

```
Outcome（望む成果）
 └─ Opportunity（顧客のニーズ・課題・願望）
     └─ Solution（解決策）
         └─ Assumption Test（仮説の検証）
```

| 層 | Torres の定義 | 例（夕食の例） |
|---|---|---|
| Outcome | チームが事業価値を生み出す方法を反映した、ビジネス上の必要 | （Torres は事業成果、プロダクト成果、トラクション指標を区別し、木の最上位にはプロダクト成果を勧める） |
| Opportunity | 満たされれば成果に繋がる、顧客の満たされていないニーズ・課題・願望 | 「お腹が空いた」「夕食に何を食べるか分からない」「料理する時間がない」 |
| Solution | 機会に応えるために提供するプロダクト・サービス・機能 | テイクアウトを頼む、外食する、ミールキットを定期購入する |
| Assumption Test | どの解決策が顧客価値と事業価値を最も生むかを評価する方法 | （解決策ごとに評価する） |

## 3. Opportunity の見つけ方

- **ストーリーベースのインタビュー**: 「最後に〜したときのことを教えてください」と、具体的な過去の話を聞く。機会はその中から出てくる。
- 最初の木を描く前に、インタビューを3〜4件行う。
- 営業の通話、サポートチケット、機能要望、分析データは、文脈が欠けるため、次のインタビューのヒントとして使う。
- **Experience Map**: 集めたストーリーを一枚に表し、その場面を木の上位の枝にする。各機会は、起きた場面の下に置く。
- 「問題」という語は避ける。願望に応えるプロダクトもあるため。

## 4. 運用ルール

- **成果は原則1つ**: 複数求められても、自分たちで優先順位をつけ、最重要の1つで木を作る。
- **機会であって解決策ではない**: 「その機会に応える方法が複数あるか」で確かめる。
- 木は3〜4件のインタビューごとに見直す。粗い初稿ができたら、対象の機会を1つ選ぶ。
- 機会の評価観点: 機会の大きさ、市場要因、会社要因、顧客要因。この段階では工数を評価しない。
- **比較して選ぶ**: 対象の機会に対して、解決策を最低3つ考える。リスクがあるとき、差別化要因のとき、革新的な解決策が要るときに特に効く。
- 解決策は、1つの機会に対応する小さなものを選ぶ。継続的な周期を保てるため。
- 新しい成果には新しい木を作る。会社全体で1本の木を作らない。
- 顧客セグメントを最上位に置くのは、チームの担当が複数の顧客層にまたがるときだけ。

## 5. よくある失敗

- 機会を頭の中で作り上げる。入力（インタビュー）が無いと木は描けない。
- 直近のインタビュー1件に過剰反応する。
- 前提（成果の定義、ターゲット顧客の仮説）を決めずに描き始める。

## 6. 他の手法との関係（筆者の整理）

- **Opportunity Canvas（Jeff Patton）**: 1つの機能やアイデアの前提を1枚に整理する。OST は、複数の機会と解決策の中から何に取り組むかを選ぶ。
- **User Story Mapping**: 決めた解決策を、ユーザーの活動の流れに沿ってストーリーに分け、スライスを切る。OST の下流に置ける。
- 上流の流れの一案: OST（何に取り組むか）→ USM（どの順で届けるか）→ ユーザーストーリー。この順序は筆者の整理で、Torres の記述ではない。
