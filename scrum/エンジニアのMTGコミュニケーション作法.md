# エンジニアのMTGコミュニケーション作法

## 概要

エンジニアはTCG・プログラミング・設計・デバッグ・DDD・Scala系などで「曖昧さを減らす訓練」を日常的にやっている。その結果、会話を聞いた瞬間に **前提 / 因果 / 矛盾 / 再現性 / 条件分岐** を自動解析しはじめてしまう。

しかし日常会話やMTGで相手が求めているのは「正確な分析」ではなく **共感・空気共有・愚痴・安心感** であることが多い。これは性格や能力の問題ではなく、**「モード切替」の問題**。

本記事は、ディレクターなど非エンジニアと話す際にエンジニアが意識すべきお作法と、MTG前に瞬間的に思い出せる短文メモをまとめる。

---

## 1. 根本にある「モード切替」問題

### なぜロジックに飛びやすいか

- TCG/プログラミング/設計/デバッグ/DDD/Scala 系を日常的にやる脳は、曖昧さを許容できない
- 会話を聞いた瞬間に前提・因果・矛盾・再現性・条件分岐を解析しはじめる

### 相手が求めているもの

| エンジニア脳が返すもの | 相手が求めていることが多いもの |
|---|---|
| 正確な分析 | 共感 |
| 即最適解 | 空気共有 |
| 仕様確定 | 愚痴 |
| 矛盾指摘 | 安心感 |

### 実務で効くテクニック: 返答を1ターン遅らせる

頭に最初に出たロジックをすぐ言わない。

- **1ターン目**: 「そうなんだ」「それ嫌だね」
- **2ターン目**: 必要なら分析

エンジニア脳は即最適解を返したくなるが、会話はレスポンス速度より **「受理された感」** の方が重要な場面が多い。

---

## 2. MTGで話しやすくなる実践系お作法

### 2.1 まず「否定ではない」を置く

技術者の質問は、相手からは反論に聞こえやすい。

❌ 「それ無理です」「その設計だと破綻します」

✅ 「方向性は理解しました」「実装観点で確認したいです」「懸念だけ共有します」

これだけで空気がかなり変わる。

### 2.2 "問題指摘"だけで終わらせない

非エンジニアは「できない理由」だけ言われると詰み感が出る。

セットで以下を添える:

- 代替案
- 制約
- コスト

**例**:
> そのままだと厳しいです。代わりにAなら2日、Bなら1週間くらいでできます。

### 2.3 正確性より会話速度を優先する場面を作る

会議中に全部を厳密化しない。特に初期段階では:

- 「ざっくり理解しました」
- 「大枠OKです」
- 「詳細は後で詰めましょう」

その場で完全定義しようとすると会議が止まる。

### 2.4 "確認"を目的化しない

エンジニアは確認を始めると深く掘ってしまう。しかし相手は、

- 意思決定したい
- 進めたい
- 合意したい

だけのことが多い。毎回 **「この質問で何を決めたいんだっけ？」** を意識すると脱線しにくい。

### 2.5 相手の言葉を翻訳してから返す

ディレクターは技術用語ではなく **「体験」** で話すことが多い。

**例**: 「サクサクにしたい」 → 初回表示速度？ 操作レスポンス？ API遅延？ アニメーション？

いきなり仕様化せず、

> 「ユーザー体感の速度を改善したいイメージですか？」

のように翻訳確認すると会話が滑らかになる。

### 2.6 "正しい人"より"進められる人"が強い

会議で評価されやすいのは、問題発見能力だけでなく **前進させる能力**。

❌ 「それ無理」
✅ 「条件付きなら可能」

## 3. MTG前メモ（短文版）

長文より瞬間的に思い出せる短文の方が効く。モニタ横・Notionトップ・MTG開始前のメモに置く運用が有効。

### 一般向け

```
理解を優先
まず共感
否定から入らない
問題だけで終わらせない
厳密化しすぎない
今の目的は何か
"正しい"より"進める"
```

### エンジニア寄り（自戒用）

```
会話デバッグ禁止
即ロジック化しない
例外処理を始めない
仕様確定を急がない
相手は感情レイヤーかも
MTGは実装レビューではない
```

## 4. まとめ

| 原則 | アンチパターン | 推奨 |
|---|---|---|
| 否定から入らない | 「それ無理」 | 「方向性は理解しました」 |
| 代替案を添える | できない理由のみ | 案A/案B + コスト |
| 厳密化しすぎない | その場で全部仕様化 | 「大枠OK。詳細は後で」 |
| 目的を忘れない | 確認を深掘り | 「何を決めたいか」確認 |
| 相手の言葉を翻訳 | 即仕様用語に変換 | 体験ベースで確認返し |
| 前に進める | 完璧な指摘 | 条件付き可能解 |
